## उद्देश्यहरू

हाम्रो मुख्य उद्देश्य योगदानकर्ताहरूले pull request पेस गरेकै क्षणदेखि उनीहरूलाई छिटो र उपयोगी प्रतिक्रिया उपलब्ध गराउनु हो। यसमा मुख्य रूपमा कोडको समीक्षा गर्ने र स्वीकृत pull request हरूलाई मर्ज गर्ने काम समावेश हुन्छ।

यसका अतिरिक्त, परियोजना सही रूपमा सञ्चालन भइरहोस् र योगदानकर्ताहरूका लागि सकेसम्म सहयोगी तथा उपयोगी बनिरहोस् भन्ने कुरा सुनिश्चित गर्नु पनि मर्मतकर्ताहरूको जिम्मेवारी हो।

## यो कसका लागि हो?

Git र GitHub को आधारभूत ज्ञान भएका जोसुकै व्यक्तिका लागि। तपाईं विशेषज्ञ हुन आवश्यक छैन। यो मार्गदर्शिका सुरुआती व्यक्तिहरूलाई समेत सहयोग गर्ने गरी तयार गरिएको हो।

यो एउटा सक्रिय परियोजना हो, जसमा नियमित रूपमा योगदानहरू प्राप्त हुन्छन् र धेरै मानिसहरूलाई आफ्नो पहिलो open-source योगदान गर्न मद्दत पुग्छ। मर्मतकर्ता हुँदा योगदानकर्ताहरूको पहिलो अनुभव सकारात्मक बनाउन र उनीहरूलाई निरन्तर योगदान गर्न प्रोत्साहित गर्न मद्दत पुग्छ।

तपाईं आफूलाई अनुकूल हुने गरी थोरै वा धेरै समय दिन सक्नुहुन्छ। मिलेर काम गर्दा हामी परियोजनालाई सहज रूपमा सञ्चालन भइराख्न मद्दत गर्न सक्छौँ।

## कार्यविधि

- परियोजनाको **Pull Requests** खण्डमा जानुहोस् र **changes requested** अवस्थामा नरहेको सबैभन्दा पुरानो pull request बाट सुरु गर्नुहोस्।
- Pull request खोल्नुहोस्, **Files changed** ट्याबमा जानुहोस् र कोड समीक्षा सुरु गर्नुहोस्।
- PR को समीक्षा गर्नुहोस् र यसले ट्युटोरियलमा उल्लेख गरिएका निर्दिष्ट मापदण्डहरू पालना गरेको छ कि छैन भन्ने सुनिश्चित गर्नुहोस्।
- HTML, लिङ्कहरू र डेटा सही छन् कि छैनन् जाँच गर्नुहोस्। आवश्यक परेको ठाउँमा कार्ड फाइलको सुरुमै राखिएको छ भन्ने सुनिश्चित गर्नुहोस्।
- मर्ज गर्दा हुने द्वन्द्वहरू (merge conflicts) जाँच गर्नुहोस्। आवश्यक भएमा ती समाधान गर्न `master` शाखालाई PR शाखामा मर्ज गर्नुहोस्। सामान्यतया fork पुरानो भएको र धेरै PR हरूले उस्तै खण्डहरूमा परिवर्तन गरेका कारण यस्ता द्वन्द्वहरू उत्पन्न हुन्छन्।
- द्वन्द्व समाधान गर्दा fork सिर्जना गरेपछि थपिएका कार्डहरूभन्दा माथि नयाँ कार्ड राख्नुहोस्।
- सबै कुरा ठीक देखिएमा PR स्वीकृत गर्नुहोस् र योगदानकर्ताले गरेको कामका लागि धन्यवाद दिँदै सन्देश लेख्नुहोस्। धेरै योगदानकर्ताहरूले पहिलो पटक योगदान गरिरहेका हुन्छन् र उनीहरूलाई प्रोत्साहनले मद्दत गर्छ भन्ने कुरा सम्झनुहोस्।
- PR लाई `master` शाखामा मर्ज गर्नुहोस्।

## परिवर्तनहरू अनुरोध गर्ने (Request changes)

- कहिलेकाहीँ pull request मा योगदानकर्ताले सच्याउनुपर्ने समस्या हुन सक्छन्। उदाहरणका लागि, गलत शाखा प्रयोग गरिएको हुनु, HTML बिग्रिएको हुनु, जानकारी छुटेको हुनु वा कार्ड गलत स्थानमा राखिएको हुनु। यस्ता समस्याहरू ट्युटोरियल सही रूपमा पालना नगर्दा उत्पन्न हुन्छन् र यी सामान्य मर्ज द्वन्द्व मात्र होइनन्।
- GitHub मा कोड समीक्षा सुरु गरेर परिवर्तनहरू अनुरोध गर्नुहोस्। सकेसम्म स्पष्ट र विस्तृत विवरण दिनुहोस्। समस्यासँग सम्बन्धित ठ्याक्कै त्यही लाइनमा टिप्पणी गर्नुहोस्, समस्या के हो भनेर स्पष्ट पार्नुहोस्, यसलाई कसरी समाधान गर्न सकिन्छ भनेर बताउनुहोस् र PR समीक्षा प्रक्रियामा यस्तो हुनु सामान्य कुरा हो भनी योगदानकर्तालाई आश्वस्त पार्नुहोस्।
- तयार भएपछि समीक्षा पेस गर्नुहोस्।
- योगदानकर्ताले थप प्रश्नहरू सोध्न सक्छन्, जसमा तपाईंले सहयोग गर्न सक्नुहुन्छ। त्यसैले छलफलमा आएका सन्देशहरूमा ध्यान दिइरहनुहोस्। हाम्रो उद्देश्य सबैलाई काम पूरा गर्न मार्गदर्शन गर्नु र सम्पूर्ण प्रक्रियाभरि योगदानकर्ताहरूलाई सहयोग गर्नु हो।
- अनुरोध गरिएका परिवर्तनहरू गरिसकेपछि pull request लाई `master` शाखामा मर्ज गर्न सकिन्छ।

परिवर्तनहरूले परियोजनालाई बिगारेका छैनन् र प्रत्यक्ष रूपमा सञ्चालन भइरहेको पृष्ठ अझै पनि अपेक्षाअनुसार काम गरिरहेको छ भन्ने कुरा सधैँ परीक्षण गर्नुहोस्। मर्ज गर्नुअघि परिवर्तनहरूलाई आफ्नै स्थानीय वातावरणमा परीक्षण गर्नु राम्रो अभ्यास हो। शङ्कास्पद देखिने कुनै पनि कुरा कहिल्यै मर्ज नगर्नुहोस्।

## उपकरणहरू (Tools)

यदि केही मात्र pull request हरू छन् भने, सम्पूर्ण समीक्षा प्रक्रिया परियोजनाको GitHub पृष्ठमै गर्न सकिन्छ।  
तर, एकै समयमा धेरै PR हरू विचाराधीन हुनु सामान्य कुरा हो, जसले मर्ज द्वन्द्वहरू निम्त्याउन सक्छ। परिवर्तनहरूको भिन्नता (diffs) समीक्षा गर्न र द्वन्द्वहरू समाधान गर्न तपाईं आफूलाई सहज लाग्ने जुनसुकै उपकरण प्रयोग गर्न सक्नुहुन्छ।

सिफारिस गरिएको एउटा उपकरण [GitKraken](https://www.gitkraken.com/download) हो। यसले दृश्यात्मक इन्टरफेस उपलब्ध गराउँछ र धेरै pull request हरू व्यवस्थापन गर्दा परियोजना व्यवस्थापनलाई सहज बनाउँछ।

GitKraken डाउनलोड गर्नुहोस्, परियोजनालाई clone गर्नुहोस् र यसलाई आफ्नो कोड सम्पादकसँगै प्रयोग गर्नुहोस्। यसमा समावेश गरिएका मर्ज द्वन्द्व समाधान गर्ने उपकरणहरूले तपाईंलाई PR हरूको कुशलतापूर्वक समीक्षा गर्न, द्वन्द्वहरू समाधान गर्न र परिवर्तनहरू मर्ज गर्न पूर्ण नियन्त्रण दिन्छन्।

योगदानकर्ताहरूले आफ्ना PR हरू जुनसुकै तरिकाले पेस गरे पनि ढाँचा एकरूप रहोस् भन्ने सुनिश्चित गर्न परियोजनाले Prettier प्रयोग गर्छ। यसले कोडबेसमा इन्डेन्टेसन र शैलीसम्बन्धी एकरूपता कायम राख्छ।

यदि HTML फाइलको ढाँचा मिलेको छैन भने, परियोजनाको मूल डाइरेक्टरीमा निम्न आदेश चलाउनुहोस्:

```js
npx prettier --write index.html
```
